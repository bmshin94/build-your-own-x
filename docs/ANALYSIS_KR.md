### 1.6 언제 쓰는가

1. **내부 동작이 궁금할 때** — Git이 왜 해시를 쌓는지, Docker가 정말 가벼운 VM인지, 가상 DOM이 뭘 하는지
2. **면접 대비** — "HTTP 서버를 직접 짜봤습니다"는 "Express 써봤습니다"와 무게가 다름
3. **주말 프로젝트 소재 선정** — 389개 중 선택
4. **새 언어 학습** — 문법 강의 대신 그 언어로 셸을 만들면 실전 감각이 붙음
5. **포트폴리오** — "직접 만든 미니 Git"은 CRUD 앱 10개보다 강함

### 1.7 단점 (냉정하게)

- **링크 썩음(link rot)**: 2013~2018년 블로그 글 다수 → 죽은 링크 존재
- **난이도 표시 없음**: 30분짜리와 3개월짜리가 나란히 있음
- **순서 없음**: 커리큘럼이 아니라 목록. 로드맵은 직접 구성해야 함
- **품질 편차**: PR 기반 수집이라 완성도가 제각각
- **상업적 배경**: CodeCrafters(유료 챌린지 플랫폼)의 마케팅 자산이기도 함

## 2. 쉽게 다시 설명하면

### 2.1 한 문장 비유

> **이건 "요리 재료"가 아니라 "전 세계 맛집 레시피 지도"입니다.**

라면(=프레임워크) 끓이는 법을 알려주는 곳이 아니라, **밀가루로 면을 뽑고 사골을 우리는 레시피**들만 모아놓은 지도입니다. 지도에는 음식이 없습니다. 음식은 각 링크를 눌러 직접 만들어야 나옵니다.

### 2.2 흔한 착각 3가지

| 착각 | 사실 |
|---|---|
| "클론하면 뭔가 실행되겠지" | ❌ 아무것도 실행 안 됨. README 하나 읽는 게 전부 |
| "설치해서 쓰는 도구겠지" | ❌ 도구가 아니라 **읽을거리 목록** |
| "안에 Git 소스코드가 있겠지" | ❌ 들어있는 건 "Git 만드는 법을 설명한 남의 블로그 주소" 7개 |

### 2.3 실제 생김새

```markdown
#### Build your own `Git`

* [**Haskell**: _Reimplementing "git clone" in Haskell from the bottom up_](http://stefan.saasen.me/...)
* [**JavaScript**: _Gitlet_](http://gitlet.maryrosecook.com/docs/gitlet.html)
* [**Python**: _Write yourself a Git!_](https://wyag.thb.lt/)
* [**Ruby**: _Rebuilding Git in Ruby_](https://robots.thoughtbot.com/...)
```

이런 줄이 **389줄** 있습니다. 그게 전부입니다.

### 2.4 왜 이게 대단한가

| 주제 | 강의/문서로 배울 때 | 직접 만들어볼 때 |
|---|---|---|
| Git | "커밋은 스냅샷이다" 암기 | SHA-1, 트리 객체, zlib 압축 구현 → **왜** 스냅샷인지 체득 |
| Docker | "격리된 프로세스" | namespace / cgroup / chroot 직접 호출 → VM이 아니라는 의미 체감 |
| React | `useState` 사용법 | 가상 DOM diff를 160줄로 구현 → **왜 key가 필요한지** 이해 |
| Database | SQL 문법 | B-Tree, WAL, 페이지 구현 → **왜 인덱스가 빠른지** 이해 |

**핵심**: 겉을 아는 사람은 많지만 속을 아는 사람은 드뭅니다. 그 격차가 연봉과 직급의 격차입니다.

### 2.5 3단계 실행 플랜

| 단계 | 기간 | 추천 |
|---|---|---|
| 1단계 워밍업 | 1~2일 | Regex Engine(200줄이면 됨), Command-Line Tool |
| 2단계 본게임 | 1~2주 | Git (Python: *Write yourself a Git!*), Web Server (*Let's Build A Web Server*) |
| 3단계 목표 직결 | 1개월+ | AI Model (LLMs-from-scratch), Bot + Docker |

**절대 하지 말 것**: 389개를 다 보려는 것. **3개만 끝까지 완주해도 상위 5%** 입니다.

**방법 C — 죽은 링크 걸러내기**

```bash
grep -oE 'https?://[^)]+' README.md | sort -u | \

**실제 학습 루틴**

| 상황 | 필요한 것 |

### 3.4 왜 GitHub에서 유명한가?

GitHub 역사상 최상위권(수십만 스타) 저장소 중 하나입니다.

1. **보편적 열등감을 정확히 건드림** — *"나는 라이브러리만 갖다 쓰는 거 아닌가?"* 라는 불안에 처방을 제시
2. **파인만 인용구의 힘** — 공유될 때 이 한 줄이 따라감. 브랜딩의 교과서
3. **진입장벽 0, 가치 100** — 설치·설정·학습곡선 없이 클릭 한 번. 스타까지의 마찰이 0
4. **스타 = 북마크** — "나중에 해봐야지"의 무덤. 실사용률보다 스타가 압도적으로 높음
5. **복리 효과** — 트렌딩 → 스타 → 노출 → PR → 목록 풍부 → 더 유명
6. **기여 문턱이 극단적으로 낮음** — 한 줄 추가 PR로 "유명 저장소 컨트리뷰터"
7. **CC0 라이선스** — 마찰 없이 복사·번역·재배포되며 확산
8. **기업의 전략적 관리** — CodeCrafters에게 완벽한 유입 깔때기라 방치되지 않고 계속 업데이트됨

### 3.5 로컬 에이전트 구축에 도움이 되는가?

**목록 자체는 직접적 도움이 없지만, 두 경로로 크게 도움이 됩니다.**

**경로 A — 내부 튜토리얼이 에이전트 기반기술과 겹침**

| 필요한 역량 | 볼 것 | README 위치 |
|---|---|---|
| LLM 내부 (토크나이저·어텐션·샘플링) | AI Model → LLMs-from-scratch | 61행 |
| RAG / 벡터 검색 | AI Model → rag-from-scratch | 61행 |
| 툴 실행 / 프로세스 제어 | Shell (7개) — fork/exec, 파이프, 리다이렉션 | 377행 |
| CLI 인터페이스 | Command-Line Tool (9개) | 126행 |
| 샌드박싱 / 격리 | Docker (6개) — namespace, cgroup | 155행 |
| 에이전트 메모리 저장소 | Database (13개) — B-Tree, WAL | 139행 |
| 배포 껍데기 | Bot (15개) — Slack/Discord | 108행 |
| 툴 호출 프로토콜 감각 | Network Stack (4개) — TCP/IP 직접 구현 | 249행 |
| DSL / 워크플로 파서 | Programming Language (41개) — 인터프리터 | 312행 |

> 특히 **Shell → Command-Line Tool → Docker** 3연타 추천.
> 로컬 에이전트가 하는 일이 정확히 "명령을 해석해 → 격리 환경에서 실행하고 → 결과를 되돌리는 것" 이기 때문입니다.

**경로 B — 이 저장소 자체를 에이전트의 먹이로 사용 (더 실용적)**

1. **파서 에이전트** — README를 `{카테고리, 언어, 제목, URL}` JSON으로 구조화
2. **링크 헬스체커 에이전트** — 죽은 링크 탐지 → 웹아카이브 대체 링크 탐색 → PR 자동 생성
3. **큐레이터 에이전트** — 목표/언어/가용시간을 듣고 로드맵 생성
4. **RAG 지식베이스** — 튜토리얼 본문을 색인해 질의응답
5. **학습 코치 에이전트** — 사용자 저장소를 보며 진도 추적, 힌트 제공

**결론**: 에이전트 프레임워크 자체는 배울 수 없지만, **에이전트가 딛고 서는 바닥**(프로세스·격리·파싱·저장소·LLM 내부)을 배우기엔 최적이며, 저장소 자체가 훌륭한 연습용 데이터셋입니다.

### 3.6 React나 PHP로 만들 수 있는가?

#### 해석 A — "이 목록 사이트를 React/PHP로 만들 수 있나?"

**네, 쉽습니다. 오히려 원본보다 나은 물건이 나옵니다.**
원본의 최대 약점이 **검색·필터 부재**(46KB 마크다운을 Ctrl+F로 뒤져야 함)이기 때문입니다.

```
React 버전 (하루면 MVP)
 1. README.md 파싱 → tutorials.json (389개)  { category, language, title, url, isVideo }

 4. 진행률 체크박스 (localStorage 또는 로그인)
 5. 링크 상태 배지 (초록=생존, 빨강=사망)
 6. 정적 생성(SSG) → Vercel 무료 배포, SEO 최적
```

```

## 4. 수익화 아이디어

> **전제**: CC0 라이선스 = 저작권 완전 포기. 복사·수정·판매 전부 합법이며 출처 표기 의무조차 없습니다(그래도 하는 것이 좋습니다).
> ⚠️ 아래 수치는 시장 관례에 근거한 **추정치**이며 보장된 값이 아닙니다.
>
> **핵심 통찰**: CodeCrafters가 이미 이 모델로 돈을 벌고 있습니다. 무료 목록으로 트래픽을 모으고 유료 자동채점 챌린지를 파는 구조로, **비즈니스 모델이 이미 검증**되어 있습니다. 남은 것은 어느 틈새를 파느냐입니다.

### 티어 1 — 지금 당장, 자본 없이 (1~4주)

#### 아이디어 1. 한국어 큐레이션 + 로드맵 사이트
- **문제**: 원본은 100% 영어, 검색 없음, 난이도 없음, 죽은 링크 방치
- **해결**: 한국어 요약 + 난이도 배지 + 소요시간 + 필터 검색 + 링크 생존 체크 + 진행률 추적
- **구축**: Next.js + README 파서 + Vercel (2~3주)
- **수익**: 애드센스 → 프리미엄 멤버십(월 4,900원) → 제휴
- **현실 기대**: 트래픽까지 6개월+. 월 10~50만원대부터
- **강점 / 약점**: 만들기 쉬움 / **누구나 따라 만들 수 있음(해자 없음)**

#### 아이디어 2. 링크 헬스체크 SaaS
- **문제**: awesome list 수천 개가 링크 썩음으로 고통. 이 저장소도 예외 아님
- **해결**: GitHub App — 주간 링크 스캔 → 죽은 링크 이슈 자동 생성 → 웹아카이브 대체 링크 PR 자동 제출
- **수익**: 공개 저장소 무료(마케팅), 비공개/기업 문서 사이트 월 $19~99
- **강점**: 타겟 명확, 고통 실재, 오픈소스 자체가 무료 마케팅 채널
- **약점**: 개인 개발자는 지불하지 않음 → 기업 문서팀 타겟팅 필요
- **평가**: **가장 저평가된 아이디어.** 시장은 작아 보이나 경쟁이 거의 없음

#### 아이디어 3. Claude Code 스킬/플러그인 패키지
```
byox-skill/
├── SKILL.md              # 학습 코치 에이전트
├── tutorials.json        # 389개 구조화 데이터
├── scripts/roadmap.py    # 목표 → 주차별 계획 생성
└── scripts/scaffold.sh   # 학습 저장소 자동 생성 + 커밋 로드맵
```
- **수익**: 무료 배포로 인지도 → 유료 확장판(기업 온보딩 커리큘럼)
- **강점**: **선점 효과.** 현재 이 영역은 거의 비어 있음
- **약점**: 시장이 아직 작음(단, 빠르게 성장 중)

### 티어 2 — 중간 투자, 확실한 수요 (1~3개월)

#### 아이디어 4. 한국어 "완주 코스" 강의 ⭐ 현실성 최고
원본이 주는 건 **링크**뿐입니다. 사람들이 원하는 건 **끝까지 손잡고 가주는 것**입니다.

- **상품 예시**: 『파이썬으로 Git 밑바닥부터 만들기 — 8주 완성』
  (주차별 영상 + 단계별 코드 + 막히는 지점 해설 + 수료 시 포트폴리오 저장소 완성)
- **채널**: 인프런 / 클래스101 / 유데미 또는 자체 판매
- **가격**: 5~15만원
- **현실 기대**: 인프런 중상위권 기준 누적 수백~수천 명, 강의당 수백만~수천만원
- **강점**: **가장 검증된 모델.** 한국어 "밑바닥부터" 강의는 여전히 희소
- **약점**: 영상 제작 노동이 큼 (강의 1개 = 2~3개월)
- **추천 소재 순서**: Git > 웹서버 > 인터프리터 > Docker (수요/난이도 균형)

#### 아이디어 5. 기업 교육 커리큘럼 납품 (B2B)
- **상품**: 신입 온보딩용 4주 "밑바닥 구현" 프로그램 + 멘토링 + 평가 루브릭
- **가격**: 기업당 500만~3,000만원
- **강점**: **객단가 압도적.** 1건 수주 = 강의 100개 판매
- **약점**: 영업 사이클이 길고 레퍼런스 없이는 진입 어려움
- **진입 전략**: 티어 1의 무료 사이트로 인지도 확보 후 첫 고객 유치

### 티어 3 — 큰 승부 (6개월+)

#### 아이디어 6. 자동 채점 챌린지 플랫폼 (CodeCrafters 벤치마킹)
- **구조**: 단계별 테스트 → 코드 푸시 → 자동 채점 → 다음 단계 해금
- **참고 가격**: CodeCrafters 월 $30~40 구독
- **차별화 (핵심)**:
  - 언어 현지화 — 한국어/일본어 (CodeCrafters는 영어 전용)
  - 분야 특화 — **AI 에이전트 챌린지**(툴콜링, RAG, MCP 서버 직접 구현)
  - 가격 파괴 — 월 9,900원
- **강점**: 구독 = 반복 매출, 자동 채점 = 한계비용 0
- **약점**: **채점 인프라가 진짜 어려움.** 다언어 샌드박스 실행·보안·비용, 최소 6개월
- **조언**: 처음부터 이걸 하지 말 것. 티어 1로 유저를 모은 뒤 전환

#### 아이디어 7. AI 학습 튜터 서비스
- 튜토리얼을 RAG로 색인해 24시간 답하는 튜터. "3장 해시 부분이 이해가 안 돼" → 사용자 코드 맥락에 맞춰 설명
- **수익**: 월 9,900~19,900원 구독
- **강점**: 에이전트 역량과 정확히 일치 — **본업 스킬업 = 제품 개발**
- **약점**: **LLM API 비용이 마진 잠식.** 헤비유저 1명이 구독료를 초과할 수 있음 → 사용량 제한 설계 필수
- **⚠️ 법적 주의**: 목록은 CC0지만 **링크된 블로그 글들은 각자의 저작권**이 있습니다. 본문 크롤링·재배포는 문제가 되므로 인용·요약 수준으로 제한하거나 저자 허락을 받으십시오.

### 추천 실행 순서

```
[1~2개월]  아이디어 3 (Claude 스킬) 무료 배포
           → 비용 0, 기술 검증, 개인 브랜딩 시작
              ↓
[2~4개월]  아이디어 1 (한국어 사이트) 런칭 + 아이디어 2 (링크체커) 부착
           → 트래픽 수집, 이메일 리스트 구축, 무료 도구로 유입
              ↓
[4~8개월]  아이디어 4 (강의 1개) 출시 — 소재: Git 또는 AI 에이전트
           → 첫 실질 매출. 사이트 유저에게 직판
              ↓
[8개월~]   매출 검증 후 아이디어 5(B2B) 또는 6(플랫폼)으로 확장
```

### 핵심 원칙 3가지

1. **목록 자체로는 돈이 안 됩니다.** CC0라 누구나 복사합니다. 돈은 **목록 위에 얹는 것**(채점·코칭·한국어·커뮤니티·완주 보장)에서 나옵니다.
2. **가장 강력한 해자는 "완주율"입니다.** 튜토리얼 시작률은 높고 완주율은 처참합니다. 완주시키는 제품이 이깁니다.
3. **에이전트 역량이 최고의 차별점입니다.** 아이디어 3·7은 아무나 만들 수 없습니다. 거기서 시작하십시오.
